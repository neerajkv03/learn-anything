# 23. Scripts & Packaging
Version: Python 3.15.2 + uv 0.13.7
Prerequisites: 22-concurrency-asyncio

## Learning goals
- After this topic, learner can write a single-file script with inline dependency metadata (PEP 723) and run it with `uv run`.
- After this topic, learner can expose a command via `[project.scripts]` entry points.
- After this topic, learner can build a wheel and source distribution with `uv build`.
- After this topic, learner can install and manage CLI tools with `uv tool`.
- After this topic, learner can publish a package with `uv publish` safely (TestPyPI first, trusted publishing).

## Sub-topics
### Single-file scripts with inline metadata (PEP 723)
- Concept: A script can declare its own Python version and dependencies in a special `# /// script` comment block at the top. `uv add --script tool.py rich` writes it; `uv run tool.py` creates a temporary environment with those packages. `uv init --script tool.py` creates a template. Shebang `#!/usr/bin/env -S uv run --script` makes it directly executable on macOS/Linux.
- Analogy: A recipe card with its shopping list stapled to the top — anyone can cook it without asking what to buy.
- Code example: `report.py` — header `# /// script` / `# requires-python = ">=3.15"` / `# dependencies = []` / `# ///`; body uses stdlib `import json` / `print(json.dumps({"status": "ok"}))`; output `{"status": "ok"}`. Second: `bash` — `uv add --script report.py rich`, `uv run report.py`; output `""`.
- Production use: Ops scripts and one-off automation shared without a full project.
- Common mistakes: Malformed block (missing `# ///` closing line); running with plain `python` (dependencies not installed).
- Sources: https://docs.astral.sh/uv/guides/scripts/#declaring-script-dependencies ; https://packaging.python.org/en/latest/specifications/inline-script-metadata/ ; https://peps.python.org/pep-0723/

### Entry points ([project.scripts])
- Concept: Packaging = turning your project into an installable unit. `uv init --package mycli` creates a `src/mycli/` layout with a build backend. `[project.scripts] mycli = "mycli:main"` creates a terminal command `mycli` that calls `main()` in the `mycli` package. `uv run mycli` runs it in development.
- Analogy: Putting a doorbell on the house: visitors press one button instead of knowing which room to walk to.
- Code example: `pyproject.toml` (`toml`) — `[project]` name `mycli` ... `[project.scripts]` `mycli = "mycli:main"` / `[build-system]` (representative, as generated by `uv init --package`); output `""`. `src/mycli/__init__.py` (filename `__init__.py`) — `def main() -> None: print("Hello from mycli!")`; output `Hello from mycli!` (explanation: shown when running `uv run mycli`).
- Production use: Internal CLIs and published tools (e.g. ruff, httpie) are exposed this way.
- Common mistakes: Wrong `module:function` path; forgetting a build system so the command isn't installed.
- Sources: https://docs.astral.sh/uv/concepts/projects/config/#entry-points ; https://packaging.python.org/en/latest/guides/writing-pyproject-toml/#creating-executable-scripts

### Building with uv build
- Concept: `uv build` creates `dist/*.whl` (wheel — ready-to-install archive) and `dist/*.tar.gz` (sdist — source archive). Version comes from `[project] version`; bump with `uv version --bump patch` (or edit). Check contents before publishing.
- Analogy: Boxing a product for shipping: a ready-to-use box (wheel) and a kit with assembly instructions (sdist).
- Code example: `bash` — `uv version --bump patch`, `uv build`, `ls dist/`; representative output `mycli-0.1.1-py3-none-any.whl` / `mycli-0.1.1.tar.gz`.
- Production use: Internal packages built in CI and uploaded to a private index.
- Common mistakes: Forgetting to bump the version (upload rejected); committing `dist/`.
- Sources: https://docs.astral.sh/uv/guides/package/ ; https://docs.astral.sh/uv/concepts/projects/build/

### Installing CLI tools with uv tool
- Concept: `uv tool install <package>` installs a CLI into its own isolated environment and puts its command on PATH; `uv tool install .` or `uv tool install --editable .` installs your own project's command; `uv tool list`, `uv tool upgrade --all`, `uv tool uninstall`. `uv tool update-shell` adds the tool directory to PATH if needed.
- Analogy: Each app in its own sealed container on your phone — updating one never breaks another.
- Code example: `bash` — `uv tool install .`, `mycli`, `uv tool list`, `uv tool uninstall mycli`; representative output `Hello from mycli!` for the `mycli` line.
- Production use: Developers install shared internal tools the same way.
- Common mistakes: Installing CLIs into a project venv; PATH not updated (`uv tool update-shell`).
- Sources: https://docs.astral.sh/uv/guides/tools/#installing-tools ; https://docs.astral.sh/uv/concepts/tools/

### Publishing with uv publish
- Concept: `uv publish` uploads `dist/` to PyPI (the public package index). Test first on TestPyPI (`--index testpypi` after configuring it in pyproject, or `--publish-url`). Prefer Trusted Publishing from CI (no long-lived token); otherwise a scoped API token via `UV_PUBLISH_TOKEN`. Never commit tokens. Published versions can't be overwritten.
- Analogy: Sending a book to the national library: once catalogued under an edition number, that edition is permanent.
- Code example: `toml` — `[[tool.uv.index]]` / `name = "testpypi"` / `url = "https://test.pypi.org/simple/"` / `publish-url = "https://test.pypi.org/legacy/"` / `explicit = true`; output `""`. `bash` — `uv publish --index testpypi`; output `""`.
- Production use: Open-source releases and private registries from a CI release job.
- Common mistakes: Publishing secrets or large files inside the package; re-uploading the same version; tokens in shell history or git.
- Sources: https://docs.astral.sh/uv/guides/package/#publishing-your-package ; https://docs.pypi.org/trusted-publishers/
